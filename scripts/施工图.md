# 施工图：诸葛神数解读重建

## 为什么做这件事

准备把插件放到公开仓。翻数据来源的时候发现 `data/SOURCES.md` 里自己写过一条：

> `zhuge_qian.json` 的来源站点无明确开源许可，**仅限个人/本地使用**；若要公开发布
> 插件，需替换为可商用或自建数据。

现在要公开发布了，这条得处理。

## 数据现状

原来的 `zhuge_qian.json` 每条有 8 个字段，按可分发性可以分成两类：

| 字段 | 内容示例 | 性质 | 能公开吗 |
|---|---|---|---|
| `poem` | 天门一挂榜，预定夺标人，马嘶芳草地，秋高听鹿鸣。 | 古籍原文 | ✅ 公有领域 |
| `commentary` | 见龙在田，利见大人。君子得之终日干干…… | 古籍注解 | ✅ 公有领域 |
| `title` | 乾变大有 | 卦名 | ✅ 公有领域 |
| `palace` | 乾宫 | 宫位 | ✅ 公有领域 |
| `fortune` | 上上签 | 签等 | ✅ 公有领域 |
| `verdict` | 大吉，事业、财运、健康、婚姻均顺遂。 | 短断语 | ⚠️ 边界模糊 |
| `interpretation` | 读了这首诗，也许会令你心花怒放…… | **现代白话长文** | ❌ 有版权 |

`interpretation` 占了全部内容字符的 **73%**（111,772 / 152,491）。也就是说
这份数据的绝大部分体积来自一个不能分发的字段。

## 有两条路，选了哪条

**路线 A：删掉 `interpretation`**

便宜，十分钟搞定。但代价是：诸葛神数会变成七个方法里唯一一个
「不配模型就看不懂」的——签诗加文言解，普通用户读起来费劲。而插件主打的
卖点恰恰是「不配模型也能用」。这条会砸自己的招牌。

**路线 B：自己重新生成**

用模型从**公有领域的签诗和文言解**出发，重写一份白话解读。
产出物版权归本项目，可以随插件以 MIT 分发。

选 B。理由不是洁癖，是 B 的成本几乎为零，而且顺手能修掉原数据里的错标。

## 怎么确定生成物是干净的

关键约束：**输入里绝对不能出现原 `interpretation` 字段。**

脚本喂给模型的只有这四项：

```
poem        签诗原文
verdict     断语
commentary  文言解
title       卦名
```

全部是公有领域内容。生成的解读是模型基于这些古文自己写的，不是对原白话文的
改写或翻译——两者之间不存在衍生关系。

这一点在 `gen_zhuge_interpretations.py` 的 `_build_user()` 里看得见：函数只
读取那几个字段，`interpretation` 从头到尾没被读过一次。

## 顺带修的坑

跑抽样的时候发现原始数据有几条 `fortune` 跟正文明显打架：

| 签号 | 标注 | 正文写的 |
|---|---|---|
| 123 | 下签 | 大吉大利，所问诸事均得圆满达成 |
| 300 | 中下签 | 大吉大利，凡事左右逢源 |
| 90 | 中下签 | 转机交运之兆，时下机运甚佳，所问大吉大利 |

所以脚本里加了一次**独立复核**：让模型只看签诗和注解，自己判一次吉凶，
结果写进 `_fortune_review`。这个字段不进最终数据，只用来人工比对——
凡是复核结果和原标注差太远的，单独拎出来看。

这属于顺手做的数据体检，不是这次的必要条件，但既然要重新跑一遍数据，
不如把质量一起过一遍。

## 施工步骤

| 步骤 | 做什么 | 判据 |
|---|---|---|
| S1 | 写生成脚本，支持并发、重试、断点续跑 | `--limit 3` 能跑通，三条都有内容 |
| S2 | 抽 3 条人工看质量 | 白话、有具体建议、不套话、长度 120-220 字 |
| S3 | 全量 384 条 | 失败 0 条，输出文件条数 = 384 |
| S4 | 质量抽查 | 空解读 0，平均字数落在 150-200 |
| S5 | 检查复核冲突 | `_fortune_review` 与原 `fortune` 差异条目单独列出来看 |
| S6 | 替换数据文件 | 插件仍能正常出签，`--limit` 抽测过 |

## 验收

最终 `data/zhuge_qian.json` 满足：

- 384 条齐全，`number` 1-384 连续
- `poem` / `commentary` / `title` / `palace` 与古籍原文一致（未改动）
- `interpretation` 全部为本项目生成
- 不含 `_fortune_review`（校对用字段不随包发布）
- 插件不配模型时也能输出可读的签文

## 复现

```bash
python gen_zhuge_interpretations.py --limit 5     # 抽查
python gen_zhuge_interpretations.py               # 全量
python gen_zhuge_interpretations.py --resume      # 续跑
```

同一份输入，不同次生成会有措辞差异——这正常，模型输出不是确定性的。
只要字段结构、条数、长度区间一致就算复现成功。
